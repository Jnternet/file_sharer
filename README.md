# file_sharer — 局域网文件记录区

一个可执行文件、一个网址。网页是一个**记录区**：谁登记了哪些文件/文件夹，别人就能看到并**点击下载**；
选择文件时**只登记文件位置**（名称/大小/相对路径/内容哈希），**不发送任何文件内容**；
数据在点击下载后才开始流动，并且**只经过服务器定向转发**——服务器不记录、不留存。

## 需求对照

| 需求 | 实现 | 验证方式 |
|---|---|---|
| 网页是记录区，记录可下载的文件/夹 | 「可下载记录」列表来自各浏览器登记的条目，按需拉取 | `transfer-loopback.test.js`「记录区是拉取来的」+ 浏览器 e2e |
| 选择文件只记录文件位置 | 登记时只读名称/大小/相对路径并本地算 SHA-256，不发一个字节 | 回环测试「登记之后零字节」+ e2e 断言零传输/零落盘 |
| 别人点「下载」才开始传输 | 点击 → `download-request` → 分享者才读文件并按 1 MiB 分块发送 | 回环测试「点击下载才传输」 |
| 服务端只做数据转发，不记录不留存 | 服务器只有"会话表 + 转发绑定"：按 `to` 转发文本、按绑定转发二进制；不落盘、无文件概念 | `tests/architecture.rs` + `tests/relay_ws.rs` 二进制原样转发 |
| 不广播 | 服务器从不主动推送；会话列表与记录区都是拉取；数据只发给请求方 | `relay_ws.rs`「有人加入/离开时静默」「第三者收不到任何消息」 |
| 不无操作直接下载 | 传输前必须点击下载；校验通过后只出现「保存」按钮，界面不做任何自动保存 | e2e：校验通过后 `savedCount=0`、下载目录为空；点「保存」后文件才落盘 |
| 最终构建产物为单产物 | 前端 `include_dir!` 编译期内嵌，`target/release/file_sharer` 是唯一必需文件 | `scripts/smoke.sh` 在空目录里只放可执行文件启动 |
| 通过网页访问 | axum 提供静态站点 + `/api/info` + `/ws`，启动打印本机/局域网地址 | `tests/http_api.rs`（10 例）+ 冒烟脚本 |
| 每次启动后都是空桶 | 服务器内存里只有在线会话与转发绑定，进程退出即清空 | `/api/info` 的 `persistence:"none"`、`records:"none"`；架构测试禁止落盘 |
| 断点续传 | 内容寻址 `shareId` + 接收端 IndexedDB 分块 + `resume-state` 协商偏移 | 回环测试「中断后只补传剩余块」+ e2e（预置分块被跳过） |
| 自动 hash 校验（上传前 / 下载完成后） | 登记时预哈希；发送中复算（查源文件被改）；接收端落盘后复算比对，失败自动重传 | SHA-256 与 `node:crypto` 全长度对照 + 篡改/重传回环测试 |
| 单文件/文件夹自动区分 | 单文件按文件登记并直接保存；多文件或带目录结构按文件夹登记（保留相对路径），完成后只提供「打包下载 .zip」 | `plan.test.js` + e2e（2 文件含子目录，ZIP 由 python3 解压校验） |
| git 小步迭代 | 每个功能一次提交（含配套测试），见 `git log --oneline` | — |
| 所有功能代码都有配套测试 | Rust 64 例 + JS 89 例 + 真实浏览器 e2e + 冒烟脚本 | `scripts/test-all.sh`、`scripts/smoke.sh`、`node scripts/e2e-browser.mjs` |

## 快速开始

```bash
cargo build --release
./target/release/file_sharer            # 默认 8080，监听 0.0.0.0
```

输出示例：

```
file_sharer 0.1.0 已启动（服务器只做定向转发：不记录、不留存）
  本机:   http://127.0.0.1:8080/
  局域网: http://192.168.1.23:8080/
  在线会话上限: 64（Ctrl+C 退出）
```

两台设备打开同一个局域网地址：

1. 分享方把文件/文件夹拖进「我的记录」区域（或点「登记文件」/「登记文件夹」）——此时只登记位置并本地算哈希；
2. 下载方页面每 3 秒拉取一次（也可点「刷新记录区」），在「可下载记录」里看到该条目；
3. 下载方点该条目的「下载」——这时分享方才开始读文件，数据经服务器**定向转发**到下载方；
4. 下载方接收完成后提示"已校验（未保存）"，**点保存/下载才真正落盘**：
   - 单文件：`保存` → 存成该文件；
   - 文件夹：只有 `打包下载 .zip` 一个入口 → 打包时显示百分比进度，
     下载得到的 ZIP 解压后就是完整目录结构（不会只保存第一个文件）。

常用参数：

```bash
file_sharer --port 9000          # 指定端口（0 = 随机空闲端口）
file_sharer --bind 127.0.0.1     # 只监听本机（默认 0.0.0.0）
file_sharer --max-sessions 20    # 在线会话上限（默认 64）
file_sharer --quiet              # 只输出错误日志
```

## 工作机制（细节见 [DESIGN.md](DESIGN.md)）

```
分享者 A ── ①登记（只发元信息，不发文件）──▶ 记录区（浏览器各自持有）
下载者 B ── ②拉取索引 ──▶ A
B ── ③点「下载」──▶ A ── ④逐块经服务器定向转发 ──▶ B ── ⑤落盘 + 复算 SHA-256
B ── ⑥用户点「保存」才写入磁盘
```

- **服务器**：只处理 `hello/sessions/relay/bind/unbind`；文本负载按 `to` 转发，二进制帧按绑定转发；
  没有广播、没有文件概念、没有落盘。
- **负载协议**（服务器不可见语义）：`index-request/index`（登记项）→ `download-request`（点击才发）
  → `manifest / resume-state / ack / file-done / transfer-done`。
- **分块**：1 MiB；数据帧 `[kind][streamId][fileIndex][chunkIndex][payload]`（大端）；
  `streamId` 让下载者可以同时从多个分享者接收。
- **校验**：流式 SHA-256（自实现——`http://192.168.x.x` 是非安全上下文，`crypto.subtle` 不可用）。
- **续传**：`shareId = sha256(路径+大小+内容哈希)` 前 32 位；接收端按 `[shareId, fileIndex, chunkIndex]`
  存 IndexedDB，再次点击下载时只补传缺失分块。
- **文件夹**：保留相对路径；下载入口只保留 store 模式 ZIP 打包（按整包字节显示进度；
  超过 4 GiB（ZIP32 上限）时界面会提示并拒绝打包）。

## 安全边界与已知限制

- **无鉴权**：任何能访问该端口的人都能看到记录并发起下载；仅限可信局域网，不要暴露到公网。
- **服务器不记录不留存**：内存里只有"谁在线"和"这条连接往哪转发"，进程退出即空；
  文件内容与文件清单都不进入服务器（由架构测试强制）。
- **分享者必须在线**：记录条目指向分享者浏览器里的文件；分享者关掉页面，条目即消失。
- **一条外出流**：服务器二进制转发按连接绑定目标，因此同一分享者同时只跑一条下载流，
  其它请求会收到 `busy` 并提示稍后重试。
- 接收数据存在**下载者浏览器**的 IndexedDB 中；必须点「保存」/「打包下载」才写入磁盘。
- 非安全上下文限制：不使用 `crypto.subtle` / `showSaveFilePicker`；保存走 `Blob` + `<a download>`。
- **选择文件夹**：优先用 File System Access（`showDirectoryPicker`，https/localhost 可用），
  否则用 `<input webkitdirectory directory multiple>`（Chromium 与 Firefox 都支持）；
  两者都不可用时界面会提示直接把文件夹拖进来（拖放同样保留目录结构、自动区分单文件/文件夹）。
- **手机访问**：自动识别移动端（含 iPadOS 桌面版 UA），**不显示「登记文件夹」**，
  只保留「登记文件」（可多选）并提示改用桌面端——移动浏览器普遍不支持选择整个文件夹。
- **Firefox 选择文件夹的已知问题**：文件夹名含中文/非 ASCII 字符时，Firefox 的 `webkitdirectory`
  会返回空列表（[Mozilla Bug 1354580](https://bugzilla.mozilla.org/show_bug.cgi?id=1354580)，至今未修），
  表现为"选完没反应"。界面会明确提示，并引导改用**拖放文件夹**（推荐，不受影响）、
  Chrome/Edge，或「登记文件」多选；Chromium/Edge 走 `showDirectoryPicker`，不受该问题影响。
- 单个 ZIP 上限 4 GiB（ZIP32），超出时降级为逐文件保存。

## 开发约定

- 协议与核心都在 `web/lib/`，且都以"可注入依赖"的方式编写（store / 转发通道 / 时钟），
  因此能在 Node 里跑完整协议回环；`web/app.js` 只做接线与渲染。
- 每完成一个功能提交一次，提交信息写清"做了什么 + 怎么验证"；
  需求级约束（单产物、零存储、无广播、无文件记录）用架构测试与不变量测试固化。
